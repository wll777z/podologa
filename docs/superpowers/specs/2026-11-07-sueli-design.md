# Sueli — website and local appointment system

The user chose the local website/request-panel option and supplied the professional name. Implement that scope using the supplied 2.AG visual system and screenshots. The previous Seed site is archived outside the checkout.

A static-only Vite app is the appropriate approach: a standalone HTML download can include the complete visual and the local request workflow. A shared database, authentication and live calendar were the alternative and were not selected. Do not represent browser-local data as shared or sent.

Public page: Sueli identity, illustrated split hero, podology and integrative service descriptions, care explorer, process, appointment form, FAQ. No claims of guaranteed results, certification or nonexistent testimonials. Images are illustrative and not portraits of Sueli.

Requests: name, optional phone, service, preferred future date and period, consent. Validate before save. Persist UUID, created timestamp and status. Panel filters by status/search; can update or delete requests, export JSON, and configure a real WhatsApp number. Local requests retain state on reload. Data is not medical history and must not ask for sensitive symptoms.

Delivery: self-contained HTML and Windows localhost launcher in a ZIP, screenshots visible in chat, verified browser workflows and production build. Do not publish or push without another user instruction.
